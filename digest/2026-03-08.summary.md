## ⚙️ AI 기법 & 아키텍처

**CLAUDE.md / AGENTS.md 실전 패턴**
- 효과적 구조: 루트 파일(≤2~3k 토큰) + 서브시스템별 소형 AGENT.md(≤200~300줄). "Protocol spec처럼 작성, 위키처럼 쓰지 말 것"
- 성능 데이터: 레포 구조·컨벤션을 앞에 배치하면 **에이전트 런타임 28%↓, 토큰 16%↓**
- 핵심 교훈: "유닛 테스트로 검증 불가한 지시사항은 시스템 파일에 넣지 말 것". 중요 규칙은 AGENTS.md + 코드 주석 + CI 체크 **세 곳에 중복** 기재
- 실패 패턴: 수천 줄짜리 거대 파일, 추상적 지시("동시성 주의") vs 구체적 지시("콜백 X 실행 시 반드시 잠금 L 획득")

**에이전트 아키텍처**
- 실제 작동하는 패턴: **단일 컨트롤러 + 다중 도구** (Manager-Tool 패턴), 명시적 핸드오프의 **Planner→Executor→Verifier** 3단계
- MCP 활용: 소규모·단일 도메인 서버(DB, 파일시스템, 외부 API)를 엄격한 스키마와 가드레일로 운영. "MCP는 에이전트 프레임워크가 아닌 transport/contract 레이어"
- 실패 패턴: 동적 에이전트 스폰·무제한 멀티에이전트 스웜 → 비용 초선형 증가, 디버깅 불가

**모델별 실사용 포지셔닝**
- **도구 사용·에이전트**: GPT-5.x, DeepSeek 강세
- **신중한 추론·멀티파일 리팩토링**: Claude 4.x
- **대량 처리·비용 민감**: DeepSeek V3/R1 (50~80% 비용 절감 보고), Llama 자체 호스팅
- 실용 스택: DeepSeek/Llama로 전체 토큰의 80~90% 처리, 클로드/GPT는 핵심 의사결정에만

## 🧬 바이브코딩 & 방법론 진화

**Spec-First 개발의 표준화**
- AI 실행 전 상세 스펙 작성 → AI가 스펙의 모호성 비판 → 수정 후 구현 지시가 표준 플로우로 정착
- 스펙 파일이 PR과 함께 버전 관리되는 "스펙 잠금" 패턴 확산

**전문가 vs 초보 구분선**
- **전문가**: `ai/` 디렉토리, ADR, 제약 파일을 레포에 체계적으로 구성. AI를 "빠르지만 실수하는 주니어"로 취급해 스코프 제한 후 위임
- **초보**: 구조 없는 채팅, 거대 파일 전체 붙여넣기, AI 출력 무검토 머지, AI에 아키텍처 결정 위임
- 핵심 격언: *"바이브코딩은 '좋은 것'이 뭔지 이미 알 때만 통한다. 모르면 그냥 Big Ball of Mud를 더 빨리 만들 뿐"*

**이번 주 새로 등장한 패턴**
- **`ai/` 퍼스트클래스 디렉토리**: `ai/tasks/`, `ai/prompts/`, `ai/chains/`를 머신 전용 서브트리로 운영
- **파일백 프롬프트 체인**: YAML로 정의된 체인을 레포에 체크인 → 빌드 파이프라인처럼 버전 관리
- **Plan→Draft→Execute→Guardrail 4단계 루프**: 값비싼 추론 모델은 Guardrail 단계에만 투입해 비용 최적화
- **AI First Reviewer**: PR마다 `ai/reviews/pr-123.md` 생성 → 구조화된 감사 추적
