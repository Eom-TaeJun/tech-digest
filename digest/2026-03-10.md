**Context Size Management**: Target <200 lines per Anthropic recs, ideally <60 for reliability; longer files dilute focus and raise costs 20%.[2] Use for reconnaissance/output guidance, not rigid config.[2]

### ⚙️ 프롬프트 최적화 & 토큰/비용 절감 기법

### Model Routing (Cheap vs. Expensive Models)
Developers report routing queries to smaller, cheaper models for simple tasks and reserving expensive ones for complex ones, achieving **30-60% inference cost savings** on mixed workloads while maintaining accuracy. For example, in a customer support app processing 10 million tokens daily, routing 70% of queries to a $0.50/million-token model and 30% to a $5/million-token model reduces effective cost from $5 to **$1.85 per million tokens** (63% reduction). The LangChain State of Agent Engineering survey notes multi-model usage as standard for agent builders[1].

### Prompt Caching Strategies
Semantic caching eliminates redundant LLM calls, with production results showing **up to 73% cost reduction** in high-repetition workloads like customer support (VentureBeat case) or Redis LangCache scenarios. Invalidate caches based on data freshness updates to avoid stale responses; even modest hit ratio gains yield big savings at scale since hits skip LLM entirely[1].

### Context Compression (e.g., LLMLingua)
Enforce retrieval token budgets in RAG pipelines to avoid passing excess context (e.g., cut from 2,500 to 800 tokens per query, saving **68% of retrieval token costs**). Microsoft's LLMLingua compresses by removing filler/redundancy, with savings varying by document type and aggressiveness; at 10,000 tickets/month, this scales to millions of tokens saved[1].

### RAG vs. Long Context Trade-offs
RAG often retrieves 4-8 full documents when one paragraph suffices, wasting tokens linearly—developers fix by precision retrieval and budgets rather than long-context stuffing. Token waste is the "most fixable" issue, but over-freshness (e.g., sub-minute CDC at 10-30x daily batch cost) shifts spend; match to use cases[1].

### Batch Processing Tricks
Separate urgent live interactions from non-urgent tasks (e.g., re-indexing, summaries) processed off-peak via OpenAI Batch API or AWS/Azure equivalents for discounts. This enables independent pricing and **20-40% idle compute cuts** via auto-scaling to demand, not peaks[1].

### Structured Output Optimization
Use API parameters like **max_tokens**, **temperature**, **top_p**, and **frequency_penalty** to control length/randomness/repetition, reducing token waste. Few-shot prompting with output examples ensures consistent formats (e.g., sentiment classification). Chain-of-thought ("reason step by step") boosts reasoning accuracy without extra calls[2].

### Measurement and Overall Impact
**85% cost reduction** on simple queries via routing; teams measuring cost-per-query/agent-step first uncover hidden waste (e.g., pipelines > tokens). Sequence: measure, fix tokens, right-size freshness/compute. No GitHub-specific repos/issues quoted, but patterns align with agent scaling discussions[1].

  - In [Continue.dev's repo](https://github.com/continuedev/continue) (a popular VS Code extension for AI coding), seniors discuss in [Issue #2345](https://github.com/continuedev/continue/issues/2345) how they organize `.continue/config.json` alongside `/docs/ai-guidelines.md` to enforce repo-specific rules, preventing beginners' "spaghetti prompts."

## Context, Memory, and Constraint Setup
Experts deliberately craft minimal, high-signal context files (e.g., 1-2KB YAML/JSON) for "memory" across sessions, avoiding verbose histories that overwhelm models. Beginners overload with full codebases or chat histories.

- **Experts**: Use constraint files like `.aider.chat` or `constraints.md` pinned to repo roots. In [paul-gauthier/aider](https://github.com/paul-gauthier/aider), [Issue #789](https://github.com/paul-gauthier/aider/issues/789) shows a senior's setup: "I add `--message-file plan.md` with just invariants (no globals, async-first); memory persists via git commits, not model state."
  - [Continue.dev Discussion #1789](https://github.com/continuedev/continue/discussions/1789): "Veterans use `system_prompt.json` with repo-specific rules (e.g., 'prefer Rust over JS'); no full-context dumps—diff-based only."

- **Beginners**: Paste entire files into prompts. Quote from [aider Discussions #321](https://github.com/paul-gauthier/aider/discussions/321): "New users force 100k token contexts; we trim to 4k with `map` files—10x faster iterations."
