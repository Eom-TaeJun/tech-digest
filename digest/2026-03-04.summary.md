## ⚙️ AI 기법 & 아키텍처

**CLAUDE.md / 컨텍스트 파일 패턴**
- **3파일 구조 정착**: `Claude.md`(전역 프로젝트 지식) + `roadmap.md`(기능 체크리스트) + `handoff.md`(세션 상태·인수인계). 세션 시작 시 3파일 로드 → 종료 시 업데이트로 컨텍스트 연속성 확보
- **컨텍스트 관리 3원칙**: ① Offload(결과물을 파일/외부 저장소로 분리) ② Isolate(서브에이전트에 토큰 집약 작업 위임) ③ Memory-to-file(handoff.md에 상태 기록). 100개 이상의 툴 목록은 컨텍스트 비대화 초래 — bash 터미널 등 원자적 툴만 유지 권장
- **MCP 서버 실전 배포 확산**: Azure Logic Apps(Dynamics 365), Dash0(옵저버빌리티), Google Java SDK(Spring Boot 세션 관리) 등 엔터프라이즈 통합 사례 증가. "AI 에이전트를 위한 USB-C"로 자리잡는 중. 주요 리스크: 과도한 툴 권한 → 컨텍스트 오염·의도치 않은 체이닝

**프롬프트 최적화 수치**
- DR-CoT 동적 프루닝: AIME 2024에서 표준 CoT 대비 3~4%p 향상, 소형 모델로 GPT-4 능가
- 가중치 자기일관성(Weighted Self-Consistency): 계산 비용 **53% 절감**, 동등 이상 정확도
- 추론 모델에서 CoT 생략: **응답시간 20~80% 단축** + 성능 +2.9%
- Adv-CoT: 12개 추론 데이터셋에서 평균 **+4.44% 개선**

## 🧬 바이브코딩 & 방법론 진화

**패러다임 전환 — 바뀌고 있는 정설**
- **"상세 프롬프트 > 간결 프롬프트"에서 역전**: 대형 컨텍스트 창 + 스마트 모델 덕분에 과도한 명세가 오히려 경직된 출력 유발. Cursor·Windsurf는 전체 저장소 인덱싱으로 정적 `.md` 규칙 파일을 사실상 대체 중
- **스펙 우선 → 바이브 우선 + 검증**: "태스크 정의(간결) → AI 플랜 리뷰 → diff 검사" 흐름으로 전환. 단, 바이브코딩 비판(보안·품질 위험)도 건재 — 하이브리드가 현재 대세
- **규칙 바운드 에이전트 → 자유형 + 인간 감독**: Cursor Agent Mode·Windsurf Cascade가 최소 제약으로 멀티파일 작업. 거버넌스는 사전 규칙이 아닌 "리뷰 게이트"로 해결

**전문가 vs 초보 구조 차이**
- 전문가: `/agents/`, `/orchestrators/` 디렉토리 분리 + Rules 파일로 세션 무관 제약 유지 + CLI 체이닝(Kiro+Aider 등) + CI/CD 통합 안전망
- 초보: 단일 툴 바이브 생성, 채팅 히스토리 의존, 테스트·스캔 생략 → "야생 불균등 결과"
- **시니어에게 바이브코딩 = 고수준 오케스트레이션**: 의도를 Rules에 기술 후 IDE에서 검토·디버깅. 비개발자에겐 전체 생성 → 수동 수정의 연속

**실제 프로젝트 한계**
- AI 에이전트의 소프트웨어 작업 가능 시간: 2019년 수초 → 2025년 2.5시간(50% 성공률) → Claude Opus 4.6 기준 **14.5시간**. 단, 성공률 80%로 높이면 20~30분으로 급감
- "아키텍처 결정·크로스파일 리팩토링"은 여전히 AI 성능 최하위 영역
- **가트너: 2027년까지 에이전트 AI 프로젝트 40% 취소 예측** — "기술 문제가 아닌 기본 건너뜀이 원인"
