#### 1. 직접적인 충돌 (Contradictions)

**🔴 [claudemd] "Vibe + 3 Examples" 기준 → Spec-First로 역전 중**

- **기존 기준**: `Vibe + 3 Examples (Less is more)` — 감각적·직관적 기술 + 최소 예시
- **충돌 신호**: `github/spec-kit` (78k★, 374★/day) 및 `affaan-m/everything-claude-code` (85k★, 1426★/day)에서 **"principles → spec → plan → implement"** 순서의 구조화된 파이프라인이 지배적 패턴으로 부상
- **핵심 역전**: 커뮤니티는 "vibe-based 반복"을 **기술 부채의 원인**으로 지목하며 Spec-Driven을 대안으로 채택 중. `Less is more`의 Vibe 접근이 초보자 패턴으로 분류되기 시작함
- **위험도**: ⚠️ MEDIUM — "Less is more" 자체는 유효하나, "Vibe" 레이블이 구식화 위험

**🔴 [skills] "Description-driven 자동 활성화" → "Dynamic Discovery"로 이동 중**

- **기존 기준**: 스킬 설명을 잘 써서 자동 활성화 유도
- **충돌 신호**: `googleworkspace/cli` (21k★, 1323★/day)에서 **런타임 스킬 디스커버리** 구현 — 태스크 파싱 기반으로 관련 툴만 동적 로딩 (프로토콜 버퍼 활용)
- **핵심 역전**: Static description → **Dynamic protocol-level discovery**. 기존 방식은 "context bloat로 인한 비용 낭비"로 명시적 비판 받고 있음
- **위험도**: ⚠️ HIGH — 현재 기준이 비용 비효율의 원인으로 지목될 수 있음

**🔴 [harness] "Python for raw data, Agent for reasoning" 분리 원칙 → Graph-based Durable State로 진화 압력**

- **기존 기준**: Logic(Python) ↔ Intelligence(Agent) 이분법적 분리
- **충돌 신호**: `microsoft/agent-framework` + 커뮤니티 7개 소스에서 **"Durable State as First-class Primitive"** 강조 — 상태가 Python 레이어도 Agent 레이어도 아닌, 별도의 독립 계층으로 명시화되는 추세
- **핵심 역전**: 2개 레이어 분리 → **3계층(Logic / State / Intelligence)** 구조로 압력
- **위험도**: ⚠️ MEDIUM — 현재 기준이 틀린 건 아니나 불완전해지는 중
